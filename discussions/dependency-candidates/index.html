依赖候选

服务端演进过程中被提到、但尚未批准的外部依赖。这里只记录候选与待定问题，不构成选型结论；按 AGENTS.md，新增 crate 需要人类先同意。

候选服务于现状待定问题
nanoidInvite Code 短 ID未引入；邀请码本身也未实现短 ID 的碰撞概率是否值得多一个依赖
tower-governor + governor限流（GCRA）已有自建固定窗口 + 登录失败锁，功能已覆盖是否用 GCRA 替换现有实现，换来的平滑性是否够
qdrant个性化记忆 / RAG未引入；rig-core 已支持多种向量后端自托管还是嵌入式，运维成本谁承担
wasmtime插件系统未引入WASI P2 ABI 稳定性与每个插件的运行时开销
rumqttcMQTT 网关 / 设备间通话未引入；当前传输只有 WebSocket是否把 MQTT 作为第二传输，还是继续单 WS
rodio音乐播放未引入播放放在服务端还是端侧，服务端播放与 TTS 输出如何共存
tokio-cron-schedulerTimer / 提醒 / 闹钟未引入单机内存调度够不够，重启后任务要不要恢复
csm.rs（AGPL-3.0）对话韵律 TTS未引入AGPL 与项目许可的兼容性未评估
voirs-emotion情绪自适应语调未引入；sherpa-onnx 已有 SER 模型与现有 SER 能力重叠，是否只差一层映射
webrtc-rsWebRTC 实时音视频未引入是否作为第三种传输，ICE/TURN 由谁部署
aec3服务端回声消除未引入；AEC 目前在端侧端侧已有 AEC 时，服务端再做一遍的收益是多少
polyvoiceSpeaker diarization未引入；sherpa-onnx 也有说话人能力与现有能力重叠，是否只需扩模型
web_socket_channelFlutter App WS未引入；App 侧 WS 尚未接入Flutter 侧传输选型是否已定

以下不是新依赖，只是现有依赖的能力扩展，不需要本表批准：

已有依赖可扩展的能力
sherpa-onnxPiper/VITS 模型（多语言 TTS）、ECAPA-TDNN/WeSpeaker（声纹）、speaker embedding（声音克隆）、SER（情绪）
rig-core向量存储后端（RAG / 记忆）、Agent/Chain/Router（任务编排）
rmcp工具市场、per-agent 工具过滤、远程 MCP

分层轮次与 VAD 调参提到过 LiveKit v1-mini 与 OpenAI 的配置模式，它们是模型/配置参考而不是 crate；是否作为 Layer 2/3 仍未决定，见路线图 Session / Listener。
