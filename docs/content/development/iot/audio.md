# 音频计量语义

ES7210 只是一个来源。页面对外暴露的是**电平**——这一刻多少 dBFS、这两秒里持续多少——而不是一串 LSB 计数，更不是原始样本。本页说明契约、屏幕参数的含义，以及这些数字为什么长这样。

## 契约

采集驱动**从不停止**。它一直在把 I2S 落下的样本折进包络，`ST` 的相位只决定面板画哪一份包络、扫描条跟不跟随实时那一份。把 `ST` 读成"录音机在录/在停"会同时读错两件事：录音时驱动并没有多做任何事，停录时它也没有少做。

一条采集 poll 是纯数据面：刷新包络、抬升**零**语义。开始与停止只由业务侧的单击决定（`intent.rs` 里的 `ToggleRecord`），且只在 Audio 页生效——别的页上的单击仍然换颜色。

相位只有三态：`IDLE`（未采，面板只画 `TAP TO REC`，不画扫描条）→ `REC`（跟随实时包络）→ `STOP`（画锁存的那一份）。`IDLE` 与 `STOP` 上单击都直接回到 `REC`，没有"继续"语义：锁存的是**停止那一刻的窗**，不是一段录音。

板级没有找到 ES7210 时 `audio_enabled` 为假，`AUDIO` 页不进入页面循环（`DisplayPage::next_page` 跳过没有能力背书的页），其余页照常。进入本页是三连击按键或三指点（`TogglePage`）。

## 参数速查

台架对着这两张表走。计量参数全在 core（`drivers/audio.rs`），与硬件无关；板级只决定往里送多少字节。

### `AUDIO` 读数列

| 标签 | 字段 | 单位 | 意义 | 对应参数 |
| --- | --- | --- | --- | --- |
| `ST` | `audio.phase` | — | `IDLE` 未采 / `REC` 跟随实时包络 / `STOP` 画锁存包络 | — |
| `MS` | `audio.elapsed_ms` | ms | 已运行的墙钟时长，**不是**样本计数 | `CAPTURE_MS` |
| `PK` | `envelope.loudest()` | dBFS | 窗内最大峰值 | `SCOPE_FLOOR_DECIBELS` |
| `RMS` | `envelope.loudest_rms()` | dBFS | 窗内最大列的 RMS | `SCOPE_FLOOR_DECIBELS` |
| `COL` | `envelope.committed()` | 列 | 已提交列数，封顶 200 | `ENVELOPE_COLUMNS` |
| `RST` | `audio.restarts` | 次 | DMA 停摆后重臂的次数 | `CaptureWatchdog` |

行尾另有两个标记：`PK` 与 `RMS` 行尾的 `DBFS` 是单位，`COL` 行尾的 `CLIP` 是削波锁存。

`COL` 涨而 `PK` 不涨，才是采集链路死了：安静房间的 `PK` 会跟着一起涨，停在 `-60` 只说明这一窗里没有任何样本到达过。`RST` 与 `COL` 一起看——两者都在动而 `PK` 是 `-60`，是驱动在反复重臂；两者都不动，是页面没在跑。

`MS` 用墙钟而非样本计数，是因为面板上其它读数都从同一个时钟打戳，迟到的 poll 不该让采集看起来比实际短。

### 刻度与图形

| 元素 | 含义 | 对应参数 |
| --- | --- | --- |
| 左侧 `0` | 0 dBFS，即柱顶 | `SCOPE_FLOOR_DECIBELS` |
| 左侧 `-24` / `-48` | 标尺刻度；虚线网格每 12 dB 一条 | `GRID_DECIBELS` |
| 左侧 `-60` | 底噪，也就是中线（实线） | `SCOPE_FLOOR_DECIBELS` |
| 中线 | 静默。柱从这里向上下两侧长，**镜像** | `WAVE_CY` |
| 一列 10 ms | 一列的时间宽度 | `COLUMN_MS` |
| 200 列 | 整个窗 2.0 s | `ENVELOPE_COLUMNS` |
| 列内实心 | 该列的 RMS，即听感音量 | `loudest_rms()` |
| 列内抖动肩部 | 峰值高出 RMS 的部分 | `released_peaks()` |
| 顶端方块 | 削波发生的那一列 | `FULL_SCALE_LSB` |
| 最高柱上的短横线 | 峰值保持：窗内最高柱及其位置 | `loudest()` |
| 左下 `2.0S` | 窗长，由常量算出 | `COLUMN_MS` × `ENVELOPE_COLUMNS` |
| `TAP TO REC` | `IDLE` 时唯一的提示，此时不画扫描条 | `AudioPhase::Idle` |

## 计量语义

表格说得清"这一格是什么"，说不清"为什么这样画"。下面四条是下一人改绘图时最容易踩的。

### 镜像刻度是反着长的

柱从中线往上、往下**同时**长，所以 0 dBFS 在带的两端，底噪在中线。一柱的高度量的不是"离顶多近"，而是"离静默多远"。标尺因此只标上半，下半是上半的镜像；两端不需要规则，因为它们就是满刻度。

把刻度按"顶是 0、往下递减"来标，会与柱的实际边缘差一个八度，而且差得很难看出——每一格都还有点东西。

### 单墨水叠印里画不出第二种灰

覆盖层是反色 `stamp_pixel`，没有第二种灰度。于是 RMS **不能**画成峰值内部的一根窄条：窄条的像素就是宽条的像素，两者相同即等于没画。

实心内芯 + 抖动肩部既是唯一可行的画法，也是更便宜的一种：抖动只点亮肩部的一半行，画满一根实心柱的调用次数还更多。`CLIP` 同理只有一种——它不是电平读数，是关于整个窗的一句话，所以用文字而不只用标记。

### 释放斜率由窗长反推，不照搬表值

仪表的常规释放是 16–20 dB/s，**这里不用**。那段衰减规律是为"会动的指针"选的：指针要快速稳定下来才能读成一个电平。而这里的一柱是过去两秒的记录，释放太慢会让单个瞬态在整窗里留下三十 dB 的尾巴——窗永远回不到静默，底噪失去意义，之后每一个事件都要对着上一个事件的尾巴来读。

`RELEASE_SHIFT = 4` 是反推出来的：每列降 1/16，即 0.56 dB/列、56 dB/s，走完 60 dB 的整个刻度用掉 107 列，在 200 列的窗内绰绰有余。第一列仍能留住一个 3 ms 瞬态，所以第一列也不能更慢。core 里的测试直接断言"回到底噪的列数 < 窗长"，参数与这条要求绑在一起。

### 对数映射的弦误差，不是量化误差

读 `log₂` 只看顶端几个位是常规做法，留下的误差常被说成"量化误差"。不是：量化只值 1/16 个八度（0.38 dB），而线性 mantissa 与真 `log₂` 之间的**弦偏差**在半八度处接近 0.5 dB，**恰好落在 −20 dBFS 附近**——也就是人说话的音量。裸弦会把 −20 dBFS 读成 −21。

16 字节修正表（`LOG2_16_CHORD_ERROR`，按解出的 mantissa 索引）把全刻度误差收进 0.02 dB。更要紧的是 `scope_height()` 与 `dbfs()` 共用同一个 `log2_16()`，柱高与数字**不可能**互相矛盾；测试里也钉住了这一点，包括"最高柱的柱高恰是 `PK` 那一行"这条不变量——释放只会把柱往下拉，所以最高的柱既不会超过窗内最大峰值，也不可能被拉低。

`PK` 与 `RMS` 同窗最高时是稳态，峰值远高于 RMS 时是敲击或瞬态。这两个数是并列的，因为峰值是一个样本的性质、RMS 才是听感音量，音频工具都画成两档而不是二选一。

## 测试

```bash
moon run iot:test        # core：计量数学、契约、状态机
moon run iot:test-bsp    # 板级：I2S 配置与缓冲
moon run iot:smoke-host  # 贯通：source → state → diagnostics
```

core 覆盖：dB 与柱高同源、dB 单调且不越顶、释放的每列下限与"窗内回底"、RMS 对稳态与单点尖峰的区别、两槽满幅信号的 RMS、削波锁存与标记随列老化、释放沿绕窗后的时间顺序、2 s 窗长、最高柱即 `PK`。

`smoke-host` 的假音源按**整轮询**供数并断言 dB 读数真的穿过了 state 层；它的峰值计数器以 `isize::MIN` 起种——电平永远 ≤ 0 dBFS，以 0 起种会让最大值永远停在"没有任何电平"。
